Pass 2 — Full API surface (api.01resolved.com/v1)

Enumerated from their public docs repo (github.com/01Resolved/docs), Aug 2026. Beta; keys via Telegram; Partner tier 600 req/min; paid tiers "available."

Project · Overview (17 endpoints)

/url/{project} · /project-overview · /dao/overview · /project-overview/legals · /legal-entity · /project-overview/token-distribution · /dao/token-supply/overview · /dao/token-supply · /dao/token-supply/chart · /project-overview/performance-package · /project-overview/tranche-ladder · /project-overview/unlock-schedule · /project-overview/ico-details · /project-overview/ico-contributor (+ /chart, /ico-list, /investors)

Notable: legal-entity and legal-docs endpoints (they index the DAO legal wrappers); performance-package/tranche-ladder/unlock-schedule = vesting analytics; ICO contributor splits including an "investors" cut.

Project · Financials (11 endpoints)

/dao/treasury/overview (price, total balance, NAV/AS, spending limit, months of runway) · /dao/treasury (every wallet, every token) · /dao/treasury/chart · /dao/asset-allocation-breakdown (+ list variant) · /dao/native-token-accounts · /dao/revenues · /dao/total-revenue · /dao/expenses · /dao/total-expense · /dao/project-timeline

Project · Movements (21 endpoints — the OpenBooks engine)

/dao/account-registry (labels, custody type, entity type, tracking mode, vesting notes) · /group · /account (+ /active, /grouped, /legacy, /{id}, /{id}/balance/onchain, /{id}/balance/offchain) · /counterparty (+ /{id}) · /movement (+ /grouped, /export/csv, /{id}, /{id}/surrounding, /filters/entity, /filters/token) · /category · /dao/movements

Notable: onchain AND offchain balances per account — OpenBooks is designed to span custodial/offchain holdings, not just wallets. /movement/{id}/surrounding = transaction context view. Categories + counterparties = a real bookkeeping schema.

Project · Proposals (26 endpoints)

/proposal (+ /filter, /analytics, /{publicKey}) · per-proposal: /orders (+ 3 CSV exports), /price-chart, /market-overview, /proposal-for-chart, /threshold-chart, /flow-chart, /pass-edge · analytics: /trade-overview, /outcome-strength, /conviction-chart, /trade-frequency-chart, /traders, /proposal-metrics-chart (comparables), /proposal-comparables · /trading-activity/{daoSlug} (+ /trading-activities) · /trading-activity/special-wallet (+ /overview) — all decision-market trades for any wallet across all projects, sortable by concentration metrics.

Engineering observations

  • ~86 documented GET endpoints; no POST/webhook surface yet → alerting still lives only in the Telegram product; no streaming/websocket API.
  • Slug inconsistency (slug vs project params across endpoint groups) documented with warnings — API grew organically; a lead engineer would want a v2 coherence pass.
  • CSV exports on trades/movements — analyst-first design (their own research is clearly the first customer of this API).
  • Wayback: first crawl of 01resolved.com on 2026-01-07 — the platform is ~8 months old.
