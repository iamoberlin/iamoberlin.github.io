Technical read — what the stack looks like from outside

Compiled 2026-08-12 from public repos, docs, and site inspection.

Frontend / app

  • Next.js App Router (their public repo pins Next 16.2.5, React 19.2.4, TypeScript, Tailwind 4, Recharts) — main app at www.01resolved.com is fully client-rendered (~50 chars of crawlable text per page; copy ships in RSC flight chunks).
  • i18n with locale routing and ICU plural messages.
  • OAuth login (/oauth/login); account-level features (Signals config, upcoming portfolio).
  • OG-image snapshot service: /api/share/snapshot?type=dao-project&slug=…&theme=dark.
  • Sitemap enumerates per-project pages + per-proposal detail pages.
  • Fonts: Open Sauce One; selection color #004386 (brand blue).

Backend / API

  • REST at api.01resolved.com/v1, x-api-key auth, pagination, per-key rate limits (Partner: 600 req/min; "paid tiers with configurable rate limits per endpoint available").
  • Endpoint groups: Project (overview, financials, movements, proposals), Decision Markets, Ownership Coin Market (global dashboard, launches, graveyard, search), API key introspection.
  • Notable endpoints: /global-dashboard/projects-launch (all projects: price, treasury, NAV, mNAV, premium/discount, runway in one call), /proposal/{pk}/pass-edge (live passing status), /trading-activity/{daoSlug}/trading-activities (every trade ever), /dao/account-registry (wallet labels, custody types, tracking modes, vesting notes).
  • Keys granted manually over Telegram → no self-serve onboarding yet.

Data layer (the hard part)

  • Solana indexing of MetaDAO's FutarchyAMM + DAO/treasury programs; ICO participation and claims; wallet-level trade histories.
  • Entity resolution / account registry: wallets labeled by name, custody type (Program/multisig/…), entity type (DAO vs contributor), tracking mode, free-text notes.
  • Transaction-classification engine — app strings expose the vocabulary: accounts, counterparties, movements, transactions, events, patterns, batches, periods, rules. This is a bookkeeping rules engine (OpenBooks) in the making.
  • Derived models: NAV = treasury stables + non-native LP side + other non-native holdings; NAV/AS (adjusted supply = total − protocol-controlled − unvested); mNAV = FDV / NAV; runway = treasury / (spend limit + other monthly expenses); TWAP/pass-edge computation; proposal metrics vs project medians; trader concentration and economic-direction tilts.
  • Forensics capability demonstrated: cross-chain funding traces (deBridge from Base), 115K-wallet scoring datasets, 24h/1w/1m cohort retention analyses.

Content & ops

  • Research: Ghost. Docs: Mintlify-style MDX repo (github.com/01Resolved/docs).
  • Deploys: Vercel and Netlify configs both present in public repo.
  • Agentic development: CLAUDE.md, AGENTS.md, .claude/ dir in their public repo — they already work with Claude Code.

GitHub deep dive (pass 3, Aug 12)

Public repos: 01Resolved/docs (Mintlify MDX), alightlabs/01Resolved-Ownership-Coin-Snapshots (per-project research-brief microsite), alightlabs/ratehopper-app (personal). The platform and API are closed-source; everything below is inferred from the public repos, commit history, and HTTP fingerprints.

  • The backend was built with VAR META, a Vietnamese dev agency. The snapshot repo's API client points at https://01resolved.var-meta.com/api/v1 (resolves to a Vietnamese IP), and a May 26 docs commit reads "Update API path prefix from /api/v1/ to /v1/ for production" — staging lived on the agency's domain before the production cutover. VAR META (var-meta.com): ~50+ engineers, Hanoi + Da Nang, blockchain/AI/AR-VR agency, collaborations with Ubisoft, Hedera, Aptos, Cardano/Emurgo. Implication for the role: the platform is at least partly agency-built; "lead engineer" likely means bringing engineering in-house and owning/transitioning that codebase.
  • Backend fingerprint: Node.js/Express-style — 404s return Express's classic "Cannot GET /path", Helmet-style CSP headers, {meta: {code, message, error}, data} JSON envelope, x-api-key auth, behind Cloudflare.
  • Frontend hosting: production www serves via CloudFront (AWS) behind Cloudflare — not Vercel — while the public microsite repo deploys to Vercel (GitHub integration) with a Netlify config as fallback and a GitHub Action that syncs secrets to Vercel.
  • Dune Analytics is a second data source: the snapshot microsite pulls cached Dune query results (2h refresh, "no credits consumed") alongside their own Treasury Intelligence API — protocol metrics (e.g., Omnipair pools/revenue) come from Dune queries, not their indexer.
  • Frontend stack confirmed: Next.js App Router (16.x) + React 19 + strict TypeScript + Tailwind 4 + Recharts. James's other repo adds Radix UI/shadcn-style components, framer-motion, TanStack Query, and wagmi/viem/RainbowKit (EVM tooling fluency).
  • James's background: commits under james@alightsystems.com (GitHub alightlabs) and james@dtravel.com (GitHub JJJSOUL, whose one repo documents Nite Protocol — Dtravel's onchain booking protocol). James appears to be/have been at Dtravel (web3 travel), which explains the "founders, investors, and finance operators" framing.
  • Engineering culture: heavy agentic development (CLAUDE.md, AGENTS.md, .claude/launch.json); 12+ commits in a day on the microsite with AI-styled commit messages; CI limited to secret syncing; no tests visible in any public repo.
  • MetaDAO upstream: github.com/metaDAOproject — 55 public repos, Rust/TypeScript monorepo programs (Anchor on Solana). Their indexer necessarily consumes these.
